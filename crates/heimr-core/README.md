# heimr-core

Domain types, the adapter contract and the command safety layer for heimr.

- **Types**: `ZoneId`, `DeviceId`, `Reading` (time, source, device, metric, value, unit, quality), `Forecast` (a `Published` or `Modelled` value for a period: issue time, `valid_from`..`valid_to`, device, metric, value, unit, quality), `Event` (kind, actor, JSON payload), climate, fan (air treatment) and switch state and commands. Every command that overrides a device carries a `Hold`: until the device's next schedule change, or for a bounded duration. Setpoints are `Setpoint`s, built against a `SetpointBand` (conservative default 15–24 °C, absolute envelope 5–30 °C) and re-checked by the actuator. All types adapters build or match are `#[non_exhaustive]`, with constructors.
- **Adapter API**: implement the typed `Adapter` trait (`descriptor()`, `new(&Config)`, `async fn run(self, ctx)`); `TypedFactory` adapts it to the object-safe `AdapterFactory`, which a host for adapters in other processes implements directly with a descriptor received at run time. Descriptors are owned data; one may declare the `source_currency` its vendor quotes, and the app then refuses an instance unless `[site].currency` matches (no conversion). Money units (`¤`, `¤/kWh`, in the currency's major unit) are refused from a kind that declares none. The `AdapterContext` holds the typed config, an emitter, a command handle, a clock, a shutdown signal and a state directory. Adapters never see the bus, the store or each other, and cannot emit as another source or actor, or with a core-reserved event kind.
- **Series templates and revisions**: a descriptor declares one `SeriesTemplate` per metric it emits (kind, unit, expected interval, time source, versioned, record-on-change, optional staleness limit and lateness bound; role `Measured`, `Forecast` or `Scheduled`, a retention class and interval series, all *provisional*: they may change when the store is added). The emitter refuses a reading or forecast without a template, in another unit, with a basis that does not match the role, or with `changed_at` present where the series is not versioned (or missing where it is). NaN and ±∞ are passed through. `Revisions` mints stable `changed_at` markers for sources without one (per key: last value and marker, `max(now, stored + 1)` on a change).
- **Telemetry for free**: the core counts what each instance emits and every command offered, delivered, shadowed, rejected, withheld or dropped, plus runs and restarts, in one serialisable `AdapterStats`. Adapters report health in one line (`ctx.health().degraded("…").await?`) and can keep custom counters and gauges (`ctx.metrics()`).
- **Safety**: the `Actuator` sits between deciders and adapters; deciders get a submit-only `CommandSubmitter`, bound to their actor name when created (core names are refused). It enforces each instance's `SafetyPolicy` (the global one, possibly narrowed per instance): setpoint band, maximum hold, declared fan levels and presets, the heating-off rule (which also covers heating-critical switches) and rate limits on monotonic time. `ResumeSchedule` is never rate-limited. Every decision is written to an `AuditLog` and awaited until durable before anything is delivered; a command whose record is not durable in time is withheld. Delivery happens only to instances configured `live` and running. **Shadow mode is the default**, and a shadow instance has no command queue at all.
- **Restarts**: command ids (`CommandId`: boot number + sequence) are unique and ordered across restarts; rate limits are rebuilt from the audit tail, counting unreadable entries as accepted commands, with a hold-off after start (on by default). A missing audit trail loses the hourly history; the hold-off is then the only limit.
- **Adapters see a restricted view**: `ContextParts` carries `InstanceStats` (health and metrics only), never the supervisor's `StatsHandle`. `AdapterFactory::prepare` is async, so an out-of-process host can validate settings and discover capabilities over its protocol.

The crate docs carry runnable examples (the crate root, `Adapter`, `SafetyPolicy`, `Setpoint`); `heimr::demo` is a complete adapter.

## Design notes
- `run` is a native `async fn` in a trait (`-> impl Future + Send`): no macro. `TypedFactory` boxes the one future per run.
- Command ids are a boot number (above every id in the audit trail, and at least the Unix second at start) plus a sequence, rather than random ULIDs: no extra dependency, and their order does not depend on the wall clock moving forwards.
- Clocks have wall time (for records) and monotonic time (for intervals): `SystemClock`, `TokioClock` (deterministic under `tokio::time::pause`), `ManualClock` (moves only when told; can step the wall clock alone).

## Testing
Unit tests plus property tests: setpoints never leave their band; over arbitrary command sequences with restarts, backward clock steps and audit failures and timeouts, shadow instances receive nothing, nothing is delivered without a durable audit record, delivered setpoints and holds stay within policy, rate limits and the boot hold-off hold in real time, and ids stay unique and ordered; provenance cannot be forged; the emitter accepts a forecast exactly when its period is ordered, within the horizon (any value, NaN and ±∞ passed through bit for bit), and money only from a kind that declares its currency; readings and forecasts need a template with their unit and a matching role; `changed_at` follows versioning; revision markers repeat for an unchanged value and strictly increase on a change, a return to an earlier value and a backward clock step included.
